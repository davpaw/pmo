# Entity metadata browser and grounded PMO Agent — proposed product work

Plan only. Extend the Logical architecture interaction pattern with an Entities tab, searchable list/relationship graph, selected-entity inspector and schema-grounded PMO Agent questions. Keep generic PMO source reusable; attached projects supply public domain metadata through a versioned contract, not copied business source or production data.

## 4.2.2 — contract, bounded metadata reader and browser

Define a validated public entity descriptor: stable id/aliases, scoped variant, defining package, business steward, consumers/workspaces, supply kind, source system, fields/types/requiredness/nullability/constraints/keys, explicit relationships/cardinality and privacy classification. Unknown properties remain unknown. Evidence per field/relationship includes repository-relative path/line/symbol, immutable source identity, declared schema version if any, generation time and coverage. Separate logical declarations, import contracts, validated schemas/types, demo shapes and unverified deployment declarations. Never imply live production schema health or complete fields from an incomplete observation.

Accept host descriptors and supported bounded static extraction without evaluating application code, importing host modules or reading rows. Contract enforcement rejects unknown properties, invalid references, unsafe paths, secret/private text, example/default/record values and excessive sizes. Reviewable metadata overrides enrich descriptions or declare a separate scoped variant; never silently erase conflicts or substitute declarations for source evidence. Explicit base/version provenance detects stale overrides. A descriptor source is not automatically an authoritative complete schema: completeness and scope must be evidenced.

Use the architecture local-root boundary and strengthen where necessary: loopback, Host/Origin checks, server-configured allowlist, no arbitrary path/root, no shell or evaluation, symlink/ignored/secret/build-output exclusions, finite bytes/files/entities/fields/time, coalesced refresh and safe errors. Report skipped/unsupported/truncated/unresolved coverage. Keep last valid snapshot on failed refresh, label stale, clear removed selection. Static hosting may show dated public metadata but cannot perform a local scan.

Entities tab: name/field search, owner/consumer/workspace/evidence/supply filters, relationship layers and inspector. Show provenance, coverage, source versions, privacy and conflicting variants. Search/list/field tables and relationship links give full keyboard/screen-reader access without the canvas. Labelled controls, visible focus, live refresh/error announcements, responsive layout, reduced motion, no keyboard trap. Local show/open/refresh commands never call a model and need no key.

## 4.2.3 — selected entity and freeform schema questions

Retain server-owned history, immutable charter, bounded sessions and tool-free model. Client submits only stable entity/field/relationship ids and snapshot identity; server resolves/revalidates a bounded metadata projection. No arbitrary file read, user-authored system context, source-root parameter, record tool or mutation tool. Display selected context and revision with clear/remove controls; context changes and delayed answers preserve their pinned identity. Resolve explicit entity mentions, distinguish scoped variants and clarify ambiguous names.

Questions such as “Does this entity have field X?” answer yes or absent only within an evidenced complete schema/version, with source citations; missing, stale or truncated metadata returns unknown. A fixture property does not prove production support; a preferred-name property does not imply pronouns. Relationships and ownership cite explicit declarations, never matching names alone. Validate model citations against the server-supplied evidence set; unsupported assertions are unverified. Treat all descriptor text as untrusted, escape output and test prompt injection. Do not send rows, examples/default values, secrets or private values to the provider or logs.

“Add field X” prepares a text schema-change proposal with source owner, privacy, affected variants/consumers/import/migration/onboarding/tests and reviewed plan/step/PR workflow. It writes no schema, metadata, plan or record. Do not duplicate plan-editor functionality. Record-value questions are unavailable here. Provider-not-configured and refresh/context errors are explicit; local browser commands still work.
